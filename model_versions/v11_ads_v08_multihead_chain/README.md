# v11 ADS V08 Multihead Chain

This version implements the workflow described in `建模流程.md` for the long
chain:

`TMRDL-TSV-BSMRDL-TSV-TMRDL-TSV-BSMRDL-TSV-TMRDL-TSV-BSMRDL-TSV-TMRDL`

The cascade has 13 device blocks and 12 RDL/TSV connection positions. The
training entry reuses the v10 ADS single-device helpers and the v10
shared-to-multihead connection-circuit training pattern, then changes the
connection circuit to the 7-parameter Appendix 1 form:

- `Cn1_scale`
- `Rn1_scale`
- `Cn2_scale`
- `Rn2_scale`
- `Cn3_scale`
- `Rn3_scale`
- `Ln1_scale`

## Flow Check

The proposed method is valid in principle, but this checkout is missing the
full-chain HFSS target S-parameters required by steps 4 and 7 of
`建模流程.md`. `HFSS_sim/LHS400_Connection2/train/` currently contains
single-device `RDL` and `TSV` samples, which are suitable for ADS calibration,
but it does not contain the 13-block v11 full-chain target.

The training entry therefore validates the required target data before running
ADS or neural-network training. If the target is missing, it writes a blocked
validation archive under the result directory instead of producing a misleading
model.

Expected full-chain target inputs:

- `HFSS_sim/LHS400_Connection2/train/V11_RDL_TSV_CHAIN_variations_record.csv`
- `HFSS_sim/LHS400_Connection2/train/V11_RDL_TSV_CHAIN/dut*.s2p`

The target CSV should contain the same structure columns used by v10:

- `pitch`
- `r_tsv`
- `h_tsv`
- `l_tmrdl`
- `w_tmrdl`
- `t_tmrdl` or `h_tmrdl`
- `l_bsmrdl`
- `w_bsmrdl`
- `t_bsmrdl` or `h_bsmrdl`
- `dut_index`
